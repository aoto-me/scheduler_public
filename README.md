# Scheduler — 多機能生産性管理アプリ

複数機能（カレンダー・ToDo・メモ・家計・健康・ファイル管理など）を統合した、多機能な生産性管理アプリです。<br/>
複数サービス（Notion・Googleカレンダー・Dropbox）に分散していたデータを一元管理し、自分の見たい形で可視化・参照することを目的に開発しました。

## フロントエンド設計

### データフロー

通信・状態管理・表示の責務を役割ごとに分けています。

```
[取得の要否を判断] ページコンポーネント
  ↓ 未取得のときだけ呼ぶ
[通信・状態更新] fetchフック
  ↓
[状態管理] Redux store ←─────────────────────┐
  ↓                                         │
[表示用データの生成] Selector                 │
  ↓                                         │
[表示・ユーザー操作] UIコンポーネント          │
  ↓ 登録・更新・削除                         │
[通信・状態更新] save / deleteフック ────────┘
```

- **通信処理の共通化** — 取得・保存・削除の各フックやコンポーネントからのAPI呼び出しは、共通フック `useHttpRequest` を経由して通信。必須ヘッダー（CSRFトークンなど）の付与とエラーハンドリングをここで共通化
- **差分更新による状態の同期** — 登録・更新・削除はレスポンスの結果をReduxへ差分反映する。サーバーが返した値を反映するため整合性を保ちつつ、再取得のための通信と画面のちらつきを避ける

### コンポーネント設計

開発効率を優先し、コンポーネント内にUIとロジックの共存を許容しています。<br/>
複数コンポーネント間で共通する処理やコンポーネント内の見通しが悪くなる場合は、hooks や utils にロジックを分離しています。

```
components/
        layout/     共通レイアウト
        ui/         汎用UIコンポーネント
        {Feature}/  機能単位のコンポーネント
pages/  ページコンポーネント
```

- **ページコンポーネント** — データ取得（API呼び出し）とページの大枠の構造を担当
- **UIコンポーネント** — 表示およびユーザー操作に関する処理を担当

## バックエンド設計

自作ルーターによるシンプルな構成で、処理の流れを追いやすいことを重視しています。

### リクエストフロー

```
ブラウザ
  ↓
Apache
  ├ 静的ファイル（フロント）
  └ APIリクエスト
        ↓
    public/index.php（ルーティング・認証などの共通処理）
        ↓
    api/{resource}/index.php（各リソース）
        ↓
    各処理（GET / POST / PUT / PATCH / DELETE）
        ↓
    MySQL
```

- `public/index.php` をフロントコントローラとし、URLパスを解析、各リソースへルーティング
- 各リソースの `index.php` 内で HTTPメソッドに応じて処理を分岐

## テスト

Playwright による E2Eテストを実装しています。

- パッケージ更新・機能追加・リファクタリング時のリグレッション防止を目的に導入
- POM（Page Object Model）で操作を分離し、テストはページオブジェクトを通して画面を操作する
- テストデータが必要な機能は fixture で事前作成・事後削除し、開発用DBの状態を汚さない

&nbsp;

## セキュリティ

- **多層認証** — HttpOnly cookie の JWT・PHPセッション・デバイスID の3つを突き合わせ、すべてが一致しなければ認証エラーとして扱う
- **ログイン試行制限** — ブルートフォース対策として、IPアドレス単位で失敗回数を記録し、連続5回失敗でそのIPからのログインをロック
- **CSRFトークン** — CSRF対策として、認証後の全APIリクエストにCSRFトークンの検証を適用
- **セキュリティヘッダー** — CSP・HSTS・X-Content-Type-Options などのセキュリティヘッダーを設定
- **脆弱性スキャン** — ZAP でパッシブスキャンとアクティブスキャンを実施し、検出したアラートを1件ずつ確認して対応

チェック項目一覧は [`docs/security-checklist.md`](docs/security-checklist.md) をご覧ください。

## 今後の展望

現在、本プロジェクトの開発は終了し、後継プロジェクトを開発しています。<br/>
最初に作ったメモアプリから約2年間、既存データとの互換性を保ちながら保守・機能追加を続けてきました。<br/>
その中で、大幅な設計の変更やリファクタリングが難しくなってたことや、依存関係の更新に時間が取られるなど、課題も出てきたため、後継プロジェクトでは以下の改善に取り組んでいます。

- **AIエージェントを前提とした開発環境** — Dev Containersによる安全な開発環境を整備し、AIエージェントを前提とした開発フローへ移行する（開発環境の検証は[便利ツール集](https://github.com/aoto-me/toolbox-app)で実施）
- **APIの再設計** — 現在はUI操作とAIチャットで同じ処理を別々に実装しているため、UI操作とAIチャットの双方から共通のAPI・ビジネスロジックを利用できる構成へ見直す
- **品質管理の自動化** — 現在、手動で行っているテスト・デプロイ・依存関係の更新をCI/CDへ移行し、継続的に品質を維持できる環境を整える
- **セキュリティの強化** — 独自チェックリストではなく、OWASP ASVSを基準とした設計・実装・検証を行う
- **UI基盤の見直し** — MUIへの依存を減らし、自作UIコンポーネントへ置き換えることで、保守性とデザインの自由度を高める

## 除外ファイルについて

本リポジトリは公開用のため、ライセンス上の理由から一部コンポーネントを除外しています。

- **リッチテキストエディタ（BlockEditor）** — Tiptapが公開していたReactテンプレート（現在は非公開）を参考に実装。再配布禁止ライセンスのため除外
- **カンバンボード（KanbanBoard）・ドラッグメニュー（DraggableMenu）** — dnd-kitの実装は、CodeSandboxで公開されていた個人開発者のコードを参考に実装。ライセンスについての記述がなく、不明なため除外
